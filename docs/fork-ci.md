# Fork CI (biz-direct/agent-orchestrator)

## Builds and releases
- `build-artifacts.yml` builds unsigned **macOS Apple Silicon** (zip) and **Linux x64** (AppImage) only. It is `workflow_dispatch` (inputs `ref`, `version`) and `workflow_call`.
- **Queue a release from the Actions tab:** Actions → "Fork release" → Run workflow. Inputs: `version` (semver, e.g. `1.2.3`, required), `ref` (default `main`), `prerelease` (bool; versions with a `-suffix` are always prereleases). It validates the version, fails if tag `v<version>` or its Release already exists, builds both targets, then creates the tag at the built commit plus the Release (the workflow-created tag does not retrigger it).
- Pushing a `v*` tag by hand (`git tag v1.2.3 && git push origin v1.2.3`) does the same.
- Release assets: `agent-orchestrator-<version>-darwin-arm64.zip`, `agent-orchestrator-<version>-linux-x64.AppImage`, `latest-mac.yml`, `latest-linux.yml` (generated by `frontend/scripts/feed.mjs`, the same script upstream uses), `digests.json`, `SHA256SUMS.txt`.
- Required repo **variable** `VITE_WORKOS_CLIENT_ID` (Settings → Secrets and variables → Actions → Variables); the build fails with a clear error if it is absent.
- The baked updater feed repo is `github.repository`; the build verifies it. The feed files are published, so the in-app updater (github provider, stable `latest` channel) reads this repo's latest non-prerelease Release.
- **Self-update status (not verified end to end):** Linux AppImage updates need no signing and should work. On macOS the updater (Squirrel.Mac) validates the code signature of the downloaded app, and these builds are unsigned, so in-app update is expected to fail with a signature error; reinstall the new zip manually.

## Installing
- **macOS:** unzip, move to Applications, then right-click → Open (first launch), or run `xattr -cr "/Applications/Agent Orchestrator.app"`.
- **Arch/Omarchy:** `chmod +x agent-orchestrator-linux-x64.AppImage && ./agent-orchestrator-linux-x64.AppImage` (needs `fuse2`; or run with `--appimage-extract-and-run`).

## Upstream sync
`sync-upstream.yml` runs daily (and on dispatch): merges `OrchestratorInc/agent-orchestrator` main into a `sync/upstream-<sha>` branch, opens a PR into `main` and merges it (auto-merge when checks are required, direct otherwise). On conflicts it opens an `upstream-sync-conflict` issue and pushes nothing. Needs secret `SYNC_PAT` (repo + workflow scopes) and "Allow auto-merge" enabled in repo settings.

## Disabled on the fork
`release-latest-guard`, `pr-review-leaderboard`, `deploy-docs` and `mac-update-e2e` are gated with `if: github.repository == '<upstream>'`.
